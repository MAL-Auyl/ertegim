# Дообучение казахского голоса Piper на записях актёра — Ертегім

Цель: взять записанный по `docs/voice/recording-script.md` и
`docs/voice/recording-instructions.md` датасет и получить свой Piper-голос
(`.onnx` + `.onnx.json`), который заменит текущий `kk_KZ-issai-high` в
`tools/prerender.py` и `server/server.js`.

## 0. Итог исследования (сентябрь 2026) — коротко

- Проект `rhasspy/piper` переведён в read-only в октябре 2025; активная
  разработка и новая лицензия (GPL-3.0, веса свободны) — в форке
  [OHF-Voice/piper1-gpl](https://github.com/OHF-Voice/piper1-gpl) (Open Home
  Foundation), актуальная версия на момент написания — v1.6.0 (июль 2026).
  Именно этот форк уже выбран в проекте — см. `IDEA.md`, раздел
  «Технические решения». Значит, инструменты обучения нужно ставить из
  `piper1-gpl`, а не из архивного `rhasspy/piper`.
- **Дообучение (fine-tuning) от существующего чекпоинта официально
  поддерживается** через флаг `--ckpt_path` в `python3 -m piper.train fit`.
  В документации прямо сказано: дообучение от чекпоинта настоятельно
  рекомендуется — это заметно ускоряет обучение и улучшает качество, даже
  если чекпоинт изначально из другого языка.
  ([TRAINING.md](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md))
- **Важная оговорка**: без правки конфигурации официально поддерживаются
  дообучения **только от чекпоинтов качества `medium`**. `kk_KZ-issai-high`
  — чекпоинт качества **`high`**, а не `medium` — см. раздел 3 (варианты и
  fallback) ниже: это главный источник риска в плане, отсюда и план B.
- Датасет для `piper.train` — CSV с разделителем `|`: для одного диктора
  `wavname.wav|Текст.`, для мультиспикерной модели —
  `wavname.wav|speaker_id|Текст.`; аудио — любой формат, читаемый librosa,
  директория указывается отдельно (`--data.audio_dir`), частота дискретизации
  по умолчанию 22050 Hz.
- Экспорт готовой модели — `python3 -m piper.train.export_onnx` из
  PyTorch Lightning `.ckpt` в `.onnx`; рядом кладётся `.onnx.json` с конфигом
  голоса (именно эту пару читают `tools/prerender.py` и `server/server.js`
  через `bins.piperVoice`/`PIPER_VOICE_KK`).
- Официальное железо, на котором тренировались голоса Piper: Threadripper
  1900X, 128 GB RAM, NVIDIA A6000 (48 GB) или 3090 (24 GB); в комьюнити есть
  отчёты об успешном дообучении на GPU с 8 GB VRAM. Для нашего масштаба
  (дообучение, а не обучение с нуля, ~40–60 минут аудио) достаточно одной
  GPU уровня RTX 3060/3090/4090 или облачной T4/A10/A100.

Источники: [OHF-Voice/piper1-gpl — TRAINING.md](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md),
[OHF-Voice/piper1-gpl (репозиторий, статус форка)](https://github.com/OHF-Voice/piper1-gpl),

## 1. Среда — Colab или RunPod

### Вариант A — Google Colab (проще, бесплатный GPU с ограничениями)

1. Открыть community-ноутбук для `piper1-gpl`
   ([Piper_Training_Notebook.ipynb](https://colab.research.google.com/github/KiON-GiON/piper1-gpl/blob/fixes/notebooks/Piper_Training_Notebook.ipynb) —
   по состоянию на обсуждение #138 умеет автоматически определять
   мультиспикерность чекпоинта и принимать прямую ссылку на внешний чекпоинт)
   либо собрать окружение вручную по шагам ниже.
2. Runtime → Change runtime type → GPU (T4 бесплатно, A100 на Colab Pro —
   заметно быстрее для 30–60 эпох дообучения).
3. Проверить, что попался GPU с ≥12–16 GB VRAM для комфортного батча;
   на T4 (16 GB) дообучение single-speaker голоса от чекпоинта — реалистично,
   но батч придётся уменьшать (см. раздел 4).

### Вариант B — RunPod / любой облачный GPU-инстанс

1. Поднять под с образом `nvidia/cuda:12.x-devel` + Python 3.10+, GPU —
   RTX 3090/4090 или A10/A100 (24 GB+ VRAM — комфортно, дообучение
   укладывается в единицы часов).
2. Установить система-пакеты и клонировать репозиторий:

```bash
apt-get update && apt-get install -y build-essential cmake ninja-build git ffmpeg

git clone https://github.com/OHF-Voice/piper1-gpl.git
cd piper1-gpl

python3 -m venv .venv && source .venv/bin/activate
pip install -e '.[train]'
./build_monotonic_align.sh
```

3. Смонтировать/скопировать датасет (`dataset/wavs/*.wav` + `dataset/metadata.csv`
   из `docs/voice/recording-instructions.md`) на инстанс.

## 2. Подготовка датасета

1. Убедиться, что все `.wav` в `dataset/wavs/` — 22050 Hz, mono, 16-bit PCM
   (см. шаг даунсемплинга в `recording-instructions.md`).
2. `dataset/metadata.csv` — pipe-delimited, **без** заголовка:
   ```
   0001.wav|Сәлем! Мен — түлкі. Кішкентай інім жоғалып кетті...
   0002.wav|Сен қайта келдің! Есіңде ме, інімді бірге іздегенбіз?
   ...
   ```
   (одноголосый датасет — без колонки `speaker_id`; она нужна только если
   записываем сразу несколько дикторов в одном датасете).
3. Прогнать препроцессинг Piper (кеширует фонемы и аудио-тензоры в
   `--data.cache_dir`, создаёт `config.json` голоса):
   ```bash
   python3 -m piper.train.preprocess \
     --language kk \
     --input-dir dataset/ \
     --output-dir dataset/cache/ \
     --dataset-format ljspeech \
     --single-speaker \
     --sample-rate 22050
   ```
   (имена флагов см. `python3 -m piper.train.preprocess --help` в конкретной
   версии — интерфейс `piper.train` менялся между релизами 1.x, сверяться
   с `docs/TRAINING.md` установленной версии перед запуском).
4. Проверить на глаз 5–10 случайных пар текст↔аудио из кеша (Piper обычно
   даёт способ прослушать/сверить после препроцессинга) — рассинхрон текста
   и звука на этом шаге дороже всего чинить постфактум.

## 3. Чекпоинт для дообучения — основной путь и fallback

### Основной путь — дообучение от `kk_KZ-issai-high`

1. Скачать веса-источник (те же файлы, что уже использует `tools/prerender.py`):
   ```bash
   wget https://huggingface.co/rhasspy/piper-voices/resolve/v1.0.0/kk/kk_KZ/issai/high/kk_KZ-issai-high.onnx
   wget https://huggingface.co/rhasspy/piper-voices/resolve/v1.0.0/kk/kk_KZ/issai/high/kk_KZ-issai-high.onnx.json
   ```
   Для дообучения `piper.train` нужен PyTorch Lightning `.ckpt`, а не `.onnx`
   — чекпоинты для обучения лежат отдельно в
   [huggingface.co/datasets/rhasspy/piper-checkpoints](https://huggingface.co/datasets/rhasspy/piper-checkpoints);
   проверить там наличие `kk/kk_KZ/issai/high` до начала работы (набор
   чекпоинтов у датасета меньше, чем набор готовых `.onnx`-голосов — не для
   всех голосов чекпоинт выложен публично). Если публичного `.ckpt` для этого
   голоса нет — писать в issues/discussions `piper1-gpl` с запросом, либо
   сразу переходить к fallback-разделу ниже.
2. `kk_KZ-issai-high` — **мультиспикерная** модель (6 спикеров; в проекте
   уже используется id `3`, см. `HERO_SPEAKER = 3` в `server/server.js`).
   Дообучать её в single-speaker голос актёра — рабочий сценарий (см.
   обсуждение #138 — «multi-speaker → single-speaker» дообучение
   подтверждено сообществом), но с двумя нюансами:
   - Датасет актёра — **без** колонки `speaker_id` в `metadata.csv`
     (одноголосый), но конфигурация модели (`--data.config_path`) должна
     соответствовать архитектуре источника (совпадающие `--model.sample_rate`,
     число каналов эмбеддинга и т. п. — брать `config.json`/`.onnx.json`
     исходного чекпоинта как шаблон, а не описывать вручную).
   - Прямая рекомендация из `piper1-gpl`: «убедитесь, что качество модели и
     качество базового чекпоинта совпадают» — здесь оба `high`, конфликта
     нет, но именно *эта* пара (multi-speaker `high` → single-speaker `high`)
     менее протоптана, чем типовой сценарий «medium → medium»; на практике
     встречались отчёты об ошибках вида `NotImplementedError: Padding size 2
     is not supported for 4D input tensor` при дообучении с `high`-чекпоинтов
     без доработок — если это воспроизведётся, использовать форк/патч из
     обсуждения #138 или руками сопоставить размерности слоёв.
3. Команда запуска (пример, флаги сверить с `python3 -m piper.train fit --help`
   установленной версии):
   ```bash
   python3 -m piper.train fit \
     --data.voice_name "ertegim-fox-kk" \
     --data.csv_path dataset/metadata.csv \
     --data.audio_dir dataset/wavs/ \
     --data.cache_dir dataset/cache/ \
     --data.config_path dataset/cache/config.json \
     --data.espeak_voice "kk" \
     --model.sample_rate 22050 \
     --data.batch_size 16 \
     --ckpt_path checkpoints/kk_KZ-issai-high.ckpt \
     --trainer.max_epochs 1000 \
     --trainer.devices 1
   ```

### Fallback — если дообучение от `kk_KZ-issai-high` не заводится

Если публичного `.ckpt` для этого голоса нет, или архитектура `high` даёт
несовместимость слоёв, которую не удаётся быстро починить — два запасных
плана, от менее к более трудоёмкому:

1. **Дообучение от другого казахского/тюркского `medium`-чекпоинта.**
   Официально поддерживаемый без доработок путь — взять любой публичный
   `medium`-чекпоинт (даже не казахский — в `piper1-gpl` прямо сказано, что
   чекпоинт из другого языка всё равно ускоряет обучение за счёт общих
   низкоуровневых акустических признаков) и дообучать на нашем датасете.
   Качество казахской фонетики будет хуже, чем от казахского источника, но
   путь надёжный и хорошо протестирован сообществом.
2. **Обучение с нуля на смеси ISSAI KazakhTTS2 + записи актёра.**
   Самый трудоёмкий, но самый надёжный по качеству казахской речи вариант:
   - Взять подмножество корпуса
     [IS2AI/Kazakh_TTS (KazakhTTS2)](https://github.com/IS2AI/Kazakh_TTS) —
     271 час, 5 профессиональных дикторов (3 женских, 2 мужских голоса),
     лицензия **CC BY 4.0** (свободно для академического и коммерческого
     использования с указанием авторства — см. `IDEA.md`, раздел про
     лицензии, и README корпуса). Для голоса лисёнка разумно взять
     подмножество одного/двух похожих по тембру женских голосов
     (десятки часов), а не весь корпус — это всё ещё требует полноценного
     обучения `piper.train fit` **без** `--ckpt_path` (или с чекпоинтом
     общего назначения не для тонкой настройки, а как старт с нуля),
     сотни эпох.
   - Реалистичная оценка: **обучение с нуля VITS-архитектуры Piper на
     десятках часов данных — по опыту сообщества это 1–3 суток на одной
     GPU уровня RTX 3090/4090 (или сопоставимой облачной A10/A100)** для
     `medium`-качества, при аккуратной настройке батча и learning rate;
     `high`-качество и/или больший объём данных — кратно дольше (до
     нескольких GPU-суток). Это принципиально дороже по времени и GPU-часам,
     чем дообучение (пункт «Основной путь» — единицы часов), поэтому
     fallback стоит выбирать только если дообучение от чекпоинта
     действительно не заводится, а не «на всякий случай».
   - После обучения на KazakhTTS2-подмножестве датасет актёра **обязательно**
     подмешивается как часть обучающих данных (не отдельный второй шаг) —
     иначе результат будет голосом диктора из корпуса ISSAI, а не голосом
     актёра проекта.

## 4. Гиперпараметры и оценка времени (дообучение, основной путь)

Ориентиры для дообучения single-speaker голоса от совместимого чекпоинта на
~40–60 минутах чистого аудио (не жёсткие правила — стартовая точка, смотреть
на loss/качество примеров на инференсе и останавливать раньше при переобучении):

- `--data.batch_size`: 16–32 на GPU с 16–24 GB VRAM; 8–12 на 8–12 GB VRAM.
- `--trainer.max_epochs`: 500–1500 эпох для дообучения такого объёма данных
  (в разы меньше, чем обучение с нуля, где счёт на тысячи-десятки тысяч
  эпох) — ориентироваться на стабилизацию loss, а не на фиксированное число.
- Оценка времени: на одной современной GPU (3090/4090/A10 и выше) дообучение
  на 40–60 минутах аудио от рабочего чекпоинта обычно укладывается в
  **2–6 часов GPU-времени** до приемлемого качества; на бесплатном Colab
  T4 — дольше (сессии Colab ограничены по времени, вероятно потребуется
  несколько запусков с восстановлением из последнего `.ckpt`).
- Периодически (каждые N эпох, в зависимости от настроек логирования) слушать
  промежуточные сэмплы инференса — обучение TTS легко «пере-сглаживает» или
  начинает звучать монотонно при слишком долгом дообучении на маленьком
  датасете; при первых признаках деградации (монотонность, артефакты) —
  останавливаться на лучшем по слуху чекпоинте, а не ждать конца плана эпох.

## 5. Экспорт в ONNX

```bash
python3 -m piper.train.export_onnx \
  --checkpoint checkpoints/ertegim-fox-kk/last.ckpt \
  --output-file kk_KZ-ertegim_fox-medium.onnx
```

Рядом с `.onnx` должен получиться (или собирается вручную из
`dataset/cache/config.json` + метаданных обучения) `kk_KZ-ertegim_fox-medium.onnx.json`
— именно эту пару файлов подключает проект.

## 6. Подключение готового голоса в проект

1. Положить оба файла в `tools/voices/`:
   ```
   tools/voices/kk_KZ-ertegim_fox-medium.onnx
   tools/voices/kk_KZ-ertegim_fox-medium.onnx.json
   ```
2. Указать путь через переменную окружения (её уже читают и
   `tools/prerender.py`, и `server/server.js` через `bins.js`):
   ```bash
   export PIPER_VOICE_KK=/home/technopark/ertegim/tools/voices/kk_KZ-ertegim_fox-medium.onnx
   ```
3. Отключить программный подъём высоты тона — новый голос актёра уже звучит
   как нужно (детский тембр создан голосом, а не питч-шифтом):
   - В `tools/prerender.py`: `PITCH = 1.0` (сейчас `1.4`).
   - В `server/server.js`: `PITCH_FACTOR = 1.0` (сейчас `1.4`, строка рядом с
     `HERO_SPEAKER = 3`).
   - Если новый голос — single-speaker (а не 6-спикерная модель, как
     `kk_KZ-issai-high`), проверить и убрать/скорректировать также логику,
     завязанную на `speaker` id (`HERO_SPEAKER`, параметр `--speaker` в
     `piper` CLI из `tools/prerender.py`) — у single-speaker ONNX-модели
     спикер один, флаг `--speaker` не нужен.
4. Пересчитать все прегенерированные аудио новым голосом:
   ```bash
   python3 tools/prerender.py --force
   ```
5. Прослушать результат (все 28 реплик героя, `public/audio/*.wav`) — в первую
   очередь фразы с сильной эмоцией (`cave_fear`, `found`, `q_courage`) и
   длинные составные фразы (`intro`, `owl_meet`) — там заметнее артефакты
   дообучения, если они есть.
6. Если что-то звучит плохо на отдельных фразах — не обязательно
   переобучать всю модель: можно точечно перезаписать 3–5 проблемных фраз
   актёром (более чёткая дикция/другая интонация) и повторить шаги 4–5,
   при необходимости дообучив ещё немного эпох на обновлённом датасете.

## 7. Лицензии (свести воедино перед публикацией/коммерциализацией)

- **Веса Piper** (см. `IDEA.md`, раздел «Технические решения»): старые
  голоса — MIT; форк `piper1-gpl` с новыми голосами и инструментами обучения
  — **GPL-3.0** (сами обученные веса при этом остаются свободными для
  использования — GPL-3.0 здесь про код тулинга/форка, не блокирует
  использование результата обучения в продукте, но копилефт-обязательства
  форка стоит перепроверить с юристом перед коммерческим релизом, если в
  продукт попадает код самого `piper1-gpl`, а не только веса).
- **Корпус ISSAI KazakhTTS2** (если используется по fallback-пути или как
  вспомогательные данные): **CC BY 4.0** — свободно для академического и
  коммерческого использования, требуется указание авторства ISSAI/Nazarbayev
  University в титрах/документации проекта.
- **Записи актёра**: отдельно оформить с актёром/студией письменное согласие
  на использование голоса в продукте (включая право на дообучение TTS-модели
  и коммерческое использование результата) — это не покрывается лицензиями
  Piper/ISSAI и обязательно нужно до продакшен-использования голоса.
