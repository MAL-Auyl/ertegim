## TL;DR

- **Голосовой пайплайн работает end-to-end**: STT (Groq + локальный Whisper fallback) → блок-лист безопасности (локальный, без сети) → LLM-классификатор ответа (fail-open) → TTS (Piper + пререндер fallback) → анимация героя. Это не идея на бумаге — это код, который сегодня можно запустить и пройти.
- **Сегодня закрыли 3 конкретных технических гэпа** из P1/P2 списка `IDEA.md`: (1) сцена больше не виснет намертво при полном отказе STT, (2) ребёнок отвечает голосом без кнопки — автоматический turn-taking через VAD, (3) на экране оператора виден статус каждого шага пайплайна вживую.
- **Самый большой оставшийся риск — не технический, а валидационный**: ни одной репетиции с живым ребёнком 3-7 лет ещё не было. Весь продукт стоит на непроверенном предположении о детской дикции и о том, что VAD-пороги вообще разумны для детского голоса.
- **Технический долг относительно заявленного**: «whitelist тем» в `IDEA.md` описан как архитектурная защита, а по факту это один захардкоженный триггер-фраза ("маған ойыншық сатып бер"), не общий механизм. Для питча по AI-safety это слабое место, если спросят напрямую.

## 2. Реестр рисков из `IDEA.md` (встроенный CEO-review) — что закрыто, что нет

`IDEA.md` уже содержит честный self-review с таблицей гэпов. Ниже — сверка с текущим кодом.

| Гэп из `IDEA.md` | Было на момент ревью | Статус сейчас |
|---|---|---|
| STT timeout | GAP, ничего не описано | **Частично закрыто.** Groq имеет `GROQ_TIMEOUT_MS=5000` + автопадение на локальный Whisper; при отказе обоих — теперь оператор видит кнопки вручную (сегодняшний фикс), а не тупик |
| STT тишина / нечленораздельно | GAP | **Не закрыто явно на уровне STT-confidence**, но VAD теперь не даёт отправить в STT совсем короткие/пустые фрагменты (`VAD_MIN_SPEECH_MS`, старое `MIN_RECORDING_MS`) |
| Safety-фильтр недоступен → CRITICAL GAP (нужен fail-closed) | Неоднозначно: whitelist или LLM-вызов? | **Закрыто по факту архитектуры** — блоклист локальный, без сети, физически не может «быть недоступен». Но см. п.4 ниже — это не whitelist, а один hardcoded триггер |
| LLM отказывается отвечать (refusal) | GAP | Частично: классификатор fail-open на ручные кнопки. Отдельного «refusal» кейса (LLM ответил, но не тем форматом) нет explicit-обработки, `parsed.label` фоллбечит на `"unclear"` при невалидном JSON — это по сути покрывает и refusal |
| TTS timeout/ошибка | GAP | **Закрыто.** Пререндеренный `.wav` fallback на каждое состояние, 2.5с leash на live-вызов |
| Комбинация фон+состояние не существует | GAP | Не актуально в текущей реализации — фон/состояние не комбинируются динамически, у каждого стейта фиксированная пара (`HERO_FOR_STATE`) |
| Нет визуального индикатора «герой думает» | Прямо указано как критично (Section 11) | **Закрыто.** Позиция `think` уже была в характерах; теперь VAD явно переключает в неё в момент завершения речи ребёнка, до получения ответа STT/LLM |
| Нет dev-лога шагов пайплайна | Section 8 | **Закрыто сегодня** (`#pipelinePanel`) |
| Chaos-тест (сеть упала на 2с посреди сессии) | Section 6, не проверено | Код теперь такой сценарий переживает (STT-фоллбек + TTS-фоллбек), но **сам тест ещё не прогнан живьём** |
| Barge-in (ребёнок начинает говорить, пока герой не договорил) | Section 4, не проработано | **Не реализовано.** VAD слушает только в `question`-состояниях; во время `speakLine()` героя микрофон не вооружён (`vadArmed=false`, т.к. `disarmVad()` вызывается на каждом `renderState`) |
| Voice prompt injection / hostile-тест | Section 3, Medium likelihood / High impact | **Не проверено.** Блоклист технически может это отловить только если фраза похожа на существующий триггер — а триггер один |
| API-ключи на демо-ноутбуке | Section 3 | Не описано технически — `.env`/`GROQ_API_KEY` через переменные окружения, но нет явного плана «что если ключ попадёт на камеру» |
| 3-5 репетиций с реальными детьми | Section 6, самое важное по приоритету | **Не сделано.** Ничего не изменилось с момента ревью — это по-прежнему главный неаудированный риск всего продукта |

## 3. Технический долг / расхождения с тем, что заявлено

- **«Whitelist тем» — на деле не whitelist.** `spike/blocklist.js` содержит ровно один захардкоженный триггер (сценарная фраза «купи мне игрушку») с fuzzy-матчингом. Это blocklist одной фразы для демо-сценария, а не общий whitelist допустимых тем разговора. Если жюри спросит «а что если ребёнок скажет что-то совсем другое не по теме» — механизм это не поймает, потому что рассчитан только на один заскриптованный edge case.
- **Rive/Lottie риг, заявленный в `IDEA.md` и подробно спроектированный в чате (7 состояний, inputs, triggers, retry-таблица) — не то, что в коде.** Реализация пошла по другому, тоже рабочему пути: SVG для совёнка, AI-сгенерированные видео-петли (Pika) + GSAP для лисёнка. Само по себе не проблема (дешевле и быстрее собрать за неделю), но **в питче не стоит показывать Rive-архитектуру как факт** — это осталось на уровне дизайн-документа, не имплементации.
- **Retry-policy проще того, что обсуждали.** В коде — один переспрос, потом авто-раскрытие правильного ответа (`app.js:439-451`). Обсуждавшаяся 4-уровневая деградация (retry → simplify → offer_choices → fallback) не реализована. Для MVP это разумное упрощение, но стоит явно об этом сказать, если спросят про error-handling глубину.
- **VAD-пороги (`VAD_START_RMS=0.02`, `VAD_SILENCE_MS=1000`) — числа "с потолка", не откалиброванные на реальный детский голос.** Первая же репетиция с ребёнком может показать, что они слишком чувствительны (ловят фоновый шум зала) или недостаточно (тихий ребёнок не пересекает порог).
